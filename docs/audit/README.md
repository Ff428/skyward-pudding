# 相对上游 0.3.1 的改动审计

这份目录记录本 fork 在 **kirklin/skyward v0.3.1** 之上做了哪些改动，用于上游发布新版本时快速判断「哪些要保留、哪些冲突、哪些可以丢」。

## 文件

| 文件 | 内容 |
|---|---|
| `changes-from-upstream-0.3.1.md` | **主文档**。全部改动的分类清单：新增 / 移植补回 / 修改上游行为，逐项写清位置、标记与同步注意点 |
| `audit-markers.tsv` | 机器可读的标记表，44 项。每行 `功能 <tab> 代码里可 grep 的标记 <tab> 所在文件（`-` 为全树搜索）` |
| `port-audit-0.3.1.md` | 上一轮 0.2.x → 0.3.1 的移植审计结论 |
| `audit-port.sh` | 审计脚本，一次性输出「有 / 需人工核 / 缺」三列 |

## 用法

拿到新上游源码后：

```sh
sh audit-port.sh /path/to/our-0.3.1 /path/to/new-upstream
```

输出三列：

- **有** — 标记还在，无需处理
- **改** — 文件还在但标记没了，上游动过这块，手工合并
- **缺** — 文件都没了，上游删掉了，决定是搬回还是放弃

`audit-markers.tsv` 里带 `[w]` 的项是**修改了上游已有行为**的地方，风险最高，合并前必看。

> 基线事实：官方 v0.2.0 与 v0.3.1 都不含下拉控制中心、记住密码、无线传输、二维码、账户行——
> 这些是本 fork 自己开发的，不是从上游搬回来的。
